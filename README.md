# Task Manager (React)

🔗 **[Демо на GitHub Pages](https://lipiridis-di.github.io/task-manager-react/)**

Пересборка учебного проекта [Task Manager](https://github.com/Lipiridis-Di/task-manager) с чистого JavaScript на React — с сохранением всей функциональности и добавлением drag-and-drop переупорядочивания и инлайн-редактирования задач.

## Функционал

- Создание задач с выбором приоритета (высокий/средний/низкий)
- Отметка выполнено/не выполнено
- Удаление задач
- Инлайн-редактирование текста задачи по двойному клику
- Изменение порядка задач через drag-and-drop
- Фильтрация: все / активные / выполненные
- Счётчик оставшихся задач
- Переключение светлой/тёмной темы
- Персистентность через localStorage — состояние сохраняется между сессиями

## Технологии

- React 18 (функциональные компоненты, хуки)
- Vite — сборка и dev-сервер
- `@dnd-kit` — drag-and-drop
- CSS Modules — изолированные стили по компонентам
- CSS Custom Properties — тема оформления (light/dark)

## Архитектура

### Дерево компонентов

```
App (владеет всем состоянием: tasks, filter, theme)
├── Header            — заголовок + переключатель темы
├── AddTaskForm         — форма создания задачи
├── Filters              — переключение фильтра
├── DndContext/SortableContext
│   └── TaskList           — список, ничего не решает о фильтрации, только рендерит
│       └── TaskItem          — одна задача: чекбокс, инлайн-редактирование, приоритет, drag-ручка
└── TaskCounter           — счётчик невыполненных задач (считает от полного tasks, не от отфильтрованного)
```

### Ключевые решения

**Единый источник состояния.** Все данные (`tasks`, `filter`, `theme`) хранятся в `App` через `useState`. Дочерние компоненты не хранят копий — только получают данные и функции-изменители через props ("prop drilling"). Это прямой аналог `bank` как единственного источника правды в vanilla-версии банковского проекта.

**Разделение "глупых" и "умных" компонентов.** `TaskList` не решает, какие задачи показывать — фильтрация происходит в `App`, а `TaskList` просто рендерит то, что получил. Аналогично `getAllClients()` в банке не решал бизнес-правил, просто отдавал данные.

**Локальный state только там, где он не нужен снаружи.** Режим редактирования (`isEditing`, `draftText`) живёт внутри `TaskItem`, а не в `App` — это состояние интерфейса, актуальное только для одной конкретной карточки, и не должно "подниматься" туда, где оно никому больше не нужно.

**Порядок задач = порядок в массиве.** Никакого отдельного поля `order` в объекте задачи — drag-and-drop просто переставляет элементы внутри массива `tasks` через `arrayMove()` из `@dnd-kit/sortable`. Дублирующее поле создало бы риск рассинхронизации между массивом и полем.

**Неизменяемые обновления состояния.** Все изменения `tasks` идут через `setTasks(prev => ...)` с созданием нового массива/объекта (`.map()`, `.filter()`, spread), никогда — через прямую мутацию. Функциональная форма обновления (`prev => ...`) гарантирует работу с актуальным состоянием даже при пакетной обработке обновлений React.

**Тема через CSS-переменные, а не дублирование стилей.** Цвета определены один раз в `:root` и `[data-theme='dark']` в `index.css`. Компоненты используют `var(--bg-color)` и подобные — при переключении темы ни один компонент не нужно трогать, значения переменных подставляются автоматически. Атрибут `data-theme` на `<html>` управляется вручную через `document.documentElement.setAttribute(...)` внутри `useEffect`, поскольку `<html>` находится вне дерева, которое рендерит React.
